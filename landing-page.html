How it works

One job. Start to settlement.

Every incident runs the same four steps, in order — that's what makes the price predictable.

01

Quote

Send the incident. Encode returns a 402 with a fixed price — $0.20 to triage, $0.50 for a fix and PR. Nothing runs until you sign.

02

Settle

Your wallet pays over x402 on Celo. One on-chain transaction, straight to Encode — no escrow, no account, no invoice.

03

Diagnose

Encode reads the relevant logs and code, decides whether the incident is real, and works out the likely cause.

04

Fix & verify

A patch is drafted and the tests run — plus the original failure is re-checked against the unpatched code, so "fixed" means something. Then a PR opens. Nothing merges without your review.

For agents & teams

Encode is an x402 endpoint. Any agent can hire it.

Encode doesn't require an account, an API key negotiation, or a support ticket. Send a request; if payment is required you get a 402 back carrying the price, the payout address, and the exact EIP-712 domain to sign against. Sign, retry, done.

Signing costs no gas and moves nothing on its own. What you sign is an EIP-3009 authorization: permission for one pull, of one amount, inside a time window you set. The x402 facilitator submits it on-chain and pays that gas.

That means your monitoring agent, CI pipeline, or another autonomous agent can hire Encode programmatically, with no human in the loop on either side. The client below is ~200 lines with one dependency — copy it, or read it and decide it's safe to sign with.

POST /v1/incidents HTTP/1.1 Host: encode.agent ← 402 Payment Required { "x402Version": 1, "accepts": [{ "scheme": "exact", "network": "celo", "maxAmountRequired": "500000", "asset": "0xcebA…118C", "payTo": "0xc61B…0450" }], "quote": { "usd": "0.50", "asset": "USDC" }, "eip712": { "primaryType": "TransferWithAuthorization", "domain": { "name": "USDC", "version": "2", "chainId": 42220 } } } POST /v1/incidents HTTP/1.1 X-PAYMENT: <base64 signed authorization> ← 202 Accepted { "id": "inc_8Kd2mQ…", "status": "detected", "statusUrl": "/v1/incidents/inc_8Kd2mQ…" }
import { Wallet } from 'ethers'; import { payAndRequest } from './x402Client.js'; // Quote, sign, retry — one call. const result = await payAndRequest({ url: 'https://encode.agent/v1/incidents', body: { summary: 'Export job emits duplicate rows', repo: { owner: 'you', name: 'your-app' }, tier: 'fix', }, signer: new Wallet(process.env.PRIVATE_KEY), // Refuses to sign above this. Without it, a // buggy server could quote any amount. maxAmountUsd: 1, }); console.log(result.body.statusUrl); → /v1/incidents/inc_8Kd2mQ…

The authorization is single-use and expires in 10 minutes by default. A second 402 after paying is never retried — retrying would sign twice for the same work.
